# T020 / LANGLO-47: content reports and corrections

Plan before implementation, 2026-10-17. Build on T017–T019; owner approved
implementation and a push after completion.

1. Write service/route/browser regressions for exact item/version linkage,
   optional comments (1000 Unicode code points), categories, owner-only reads,
   duplicate taps, inaccessible targets and no content mutation. Cap creation at
   100 reports per owner per UTC day; replay does not consume capacity.
2. Add an additive `content_reports` table with owner, submission identity,
   content-version/skill/language and optional question references. A null
   question targets the lesson of that version. Match composite foreign keys to
   the existing ownership/content conventions. Migrate disposable fixtures only.
3. Add a server-only report service. Validate enrollment and current/pinned
   historical version; assessment holdouts can be reported only after the
   owner's completed attempt. Client owner IDs cannot select identity. A report
   never calls the content importer, evaluator or scheduler.
4. Add a normal form to the lesson page (with the exact item/version target when
   an exercise is present), a report form for completed assessment responses,
   and `/app/reports` for the owner's latest 100 reports. Escape text with Svelte's
   normal rendering. Keep previous study and sign-out flows working.
5. Document code-based correction through a reviewed new content version and
   existing importer. Preserve prior attempts/rubrics; quarantine old items
   through the existing one-way status path. Reuse the quarantine-at-write tests
   and add correction/version-history coverage.
6. Add the new table to private-state snapshots, extend migration inventory
   tests and verify positive upgrade/data preservation. Do not add a validator
   script or change CODEOWNERS unless a new validator twin actually needs it.
7. Run all required checks on the final combined code, review the diff, address
   high-severity findings and push the completed branch. Do not open a PR,
   deploy, call a live provider, or change tracker acceptance states.
