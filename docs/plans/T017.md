## Design and sequence

1. First reproduce premature assessment evaluation disclosure through existing
   study readers. Hide evaluations until completion in the shared readers,
   including the attempt API. Test both owners and paused/completed states.
2. Save a bounded, versioned assessment question plan on its session. Sample
   one untouched holdout per available skill from the newest non-quarantined
   content, deterministically: up to 12 questions, with up to six A1 questions
   and six A2 questions for A2 enrollments. Use A1 capacity when fewer A2 items
   exist, and conversely. A1 enrollment samples A1 only. Explain limited coverage;
   do not claim CEFR certification or a calibrated placement score.
3. Add server-only assessment planning/read services and additive fixture-only
   migrations. Validate planned questions again during submission; reject
   out-of-plan, out-of-order and quarantined questions. Complete the session in
   the same transaction as its final answer. Save an explicit not-sure flag and
   evaluate it as uncertain, including multiple choice.
4. Add authenticated assessment start/session/results pages using the existing
   Exercise component. Hide all assessment feedback until completion, including
   on reload and direct API calls. Results separate correct, incorrect and
   uncertain and list A1 topics needing further practice without writing mastery.
5. Add immediate, reload-safe practice feedback and an assisted retry action.
   Derive assisted status on the server; replay retains original attempt identity.
   An already exposed question in another session cannot regain independent
   status by changing client input. Do not show lessons/solutions for assessment
   holdouts through the practice session interface.
6. Exercise real rendered start, submit, reload, not-sure, results and practice
   retry behavior with synthetic users against the built server. Run all required
   repository checks using Node 24.19.0 / npm 11.9.0. Record red/green and limits
   in `docs/evidence/T017.md`.

Reuse existing owner-scoped SQL transactions, guarded fixture databases, content
versions, form validation, Exercise and page styling. No provider integration,
T016 merge, mastery calculation, flashcard changes, curriculum edit, dependency
upgrade or CI modification. T016's accepted fallback is available through its
existing runtime adapter; all validation uses synthetic fixtures and fake
providers, with no real provider calls. The owner subsequently authorized
LANGLO-44 through LANGLO-47 and a push after completion. Deployment and live
provider/Windows/release acceptance remain separate from local test success.
