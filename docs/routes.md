# Foundation route policy

LANGLO-44–47 add authenticated assessment start/resume, completed results,
grammar map/progress and owner-only content reports. Their routes inherit the
existing `/app/**` no-store/noindex policy and verified-session ownership guard.

Study answer and rating actions require JavaScript; keep their controls disabled until scripts are running rather than submitting plain forms ([owner decision](decisions.md)). This rule applies to study actions only and does not change auth-form behavior.

Confirmed eligible practice mistakes can be saved as editable Basic or
T003-bounded Cloze drafts through `/app/api/attempts/[id]/card`. Drafts stay
out of scheduler state until the owner approves them; their stable card ID is
derived from the note ID. Review submissions use UUID idempotency keys, and
their append-only events include the resulting scheduler snapshot.

Lesson and completed-result `?/report` actions retain exact item/version and
bounded plain text. The lesson answer action supports server-classified assisted
retries and Not sure. Existing attempt API reads also hide active/paused
assessment evaluations; expected answers are never serialized with an unfinished
assessment. See `docs/scoring-policy.md` and `docs/content-maintenance.md`.

The private route guard is deny-by-default: without a verified database session `/app/**` GET redirects to `/login` and mutations return 401. If auth cannot be resolved because data/auth configuration or the provider is unavailable, private routes return safe 503s. Owner-scoped service queries and composite constraints exist, but database tables alone do not establish route-level privacy isolation or complete learner-journey acceptance; cross-owner route acceptance remains pending. The runtime supports explicitly configured remote libSQL, but that source capability is not evidence of a provisioned or deployed production database; local tests use disposable fixtures.

T010b implemented the initial contract from [auth.md](auth.md): Better Auth 1.7.7 serves `/api/auth/**`, real `/login` `/recover` `/reset` forms replace the placeholders, and a minimal `/app` landing with sign-out exists. The owner revised the registration policy on 2026-10-13; this branch adds `/signup` and isolates mail/config failures by feature. Prototype routes under `/prototype` remain synthetic and unaffected. Cross-owner route acceptance remains pending.

LANGLO-40 adds `POST /app/api/study-sessions/[id]/pause`, `POST .../resume` and `GET .../next?skill=`. All three derive the learner from the verified session; another learner's session is 404 and unchanged. The next item comes from confirmed attempts, never returns the expected answer, and excludes holdouts outside assessment sessions. Sessions do not expire. A skill a session has started stays on the content version of its first attempt, even after a newer import; a session that has not started it reads the newest version. An answer to a question of a different version than the one the session's first answer pinned is a 409 (`STALE_QUESTION`); a second independent answer to the same question in a session is a 409 (`QUESTION_ALREADY_ANSWERED`); paused or withdrawn reads answer 409 with their own message.

LANGLO-284 adds owner-scoped Library APIs: `GET /app/api/library`, `GET/PATCH/DELETE /app/api/library/{id}`, `GET /app/api/library/{id}/file`, `POST /app/api/library/{id}/study`, and `POST /app/api/library/{id}/vocabulary`. The file route serves retained originals only to their owner; study sends only reader-supplied selected/adjacent sentences and, for lookup, the selected term. Library AI requires both `OPENAI_API_KEY` and `TYPESAFE_API_KEY`; the preflight guard, context ceiling, and daily quotas are defined in [Library services](library-services.md). No live provider or production acceptance is claimed; see [LANGLO-284 evidence](evidence/LANGLO-284.md).
