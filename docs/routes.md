# Foundation route policy

LANGLO-44–47 add authenticated assessment start/resume, completed results,
grammar map/progress and owner-only content reports. Their routes inherit the
existing `/app/**` no-store/noindex policy and verified-session ownership guard.

| New route                              | Behavior                                                                                                          |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `/app/assessment`                      | Enrolled tracks and the owner's unfinished saved assessments.                                                     |
| `/app/assessment/[language]`           | Start a bounded, saved holdout assessment for an enrolled language.                                               |
| `/app/assessment/session/[id]`         | Saved question order, Not sure and reload/resume; no feedback before completion.                                  |
| `/app/assessment/session/[id]/results` | Results only after completion; earlier requests return 409 and foreign IDs return 404.                            |
| `/app/map` and `/app/progress`         | Owner's versioned grammar evidence, explanations and manual lesson links; unenrolled language filters return 404. |
| `/app/reports`                         | Owner's latest 100 content reports; no content-editing action.                                                    |

Lesson and completed-result `?/report` actions retain exact item/version and
bounded plain text. The lesson answer action supports server-classified assisted
retries and Not sure. Existing attempt API reads also hide active/paused
assessment evaluations; expected answers are never serialized with an unfinished
assessment. See `docs/scoring-policy.md` and `docs/content-maintenance.md`.

The private route guard is deny-by-default: without a verified database session `/app/**` GET redirects to `/login` and mutations return 401. If auth cannot be resolved because data/auth configuration or the provider is unavailable, private routes return safe 503s. Database tables alone do not establish privacy isolation of an API or usable learner journeys; T011 still owns query-authorization hardening. Only local fixtures are used in this slice.

T010b implemented the initial contract from [auth.md](auth.md): Better Auth 1.7.7 serves `/api/auth/**`, real `/login` `/recover` `/reset` forms replace the placeholders, and a minimal `/app` landing with sign-out exists. The owner revised the registration policy on 2026-10-13; this branch adds `/signup` and isolates mail/config failures by feature. Prototype routes under `/prototype` remain synthetic and unaffected. Cross-owner route acceptance remains pending.

LANGLO-40 adds `POST /app/api/study-sessions/[id]/pause`, `POST .../resume` and `GET .../next?skill=`. All three derive the learner from the verified session; another learner's session is 404 and unchanged. The next item comes from confirmed attempts, never returns the expected answer, and excludes holdouts outside assessment sessions. Sessions do not expire. A skill a session has started stays on the content version of its first attempt, even after a newer import; a session that has not started it reads the newest version. An answer to a question of a different version than the one the session's first answer pinned is a 409 (`STALE_QUESTION`); a second independent answer to the same question in a session is a 409 (`QUESTION_ALREADY_ANSWERED`); paused or withdrawn reads answer 409 with their own message.
