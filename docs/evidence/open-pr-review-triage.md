### Additional findings confirmed from summary-only comments

1. **Content-revision immutability gap — valid, repaired in the approved follow-up.**
   Cited in the summaries on #47, #51, #53, #60 and #69. A disposable real-database
   probe imports an approved package, changes one valid multiple-choice answer
   under the same content/question IDs, and supplies curriculum 1.1.0. The importer
   accepts it with zero version/question writes. The same changed answer under the
   original curriculum instead raises CONTENT_CONFLICT through its package hash.
   Thus sameQuestions checking only IDs/formats is a real gap across newer curriculum
   packages, not an unconditional bypass of the curriculum fingerprint. Fixing this
   required server-side content identity/storage work outside the original edit scope.
   The owner subsequently approved the focused repair; see
   [content-version immutability evidence](content-version-immutability.md).
   The later CI review's legacy-upgrade and unchanged-version findings were
   separately approved for repair: recorded-package adoption and 16 new content
   revisions are documented in that evidence, including pre-0007 upgrade tests.
2. **Module ID is not bound to its filename — valid test gap, repaired locally.**
   Cited in #47's summary. An in-memory filesystem overlay changes English A2
   module 06's module_id to en-a2-module-05 while leaving the actual file and lessons
   unchanged. Before the follow-up fix, the shared suite passed all 285 tests and read the
   existing module-05 evidence. A new identity check now rejects that mismatch and validates all 31 module filenames. No on-disk module was edited by this probe.
3. **Gladly gloss for lieber — valid low-severity wording issue, repaired locally.**
   Cited only in #62's summary. de-a2-015 q07 gives (gladly) but expects the comparative
   lieber in a comparison. A comparative cue such as rather would be clearer;
   the cue is now rather, with an observed failing assertion before the content fix.
4. **Reusable dependency-review workflow test and OSSAR parser coverage — valid
   observations, optional guards.** #46's summary correctly notes no dedicated test
   for that workflow and a first-tools-match parser. The current OSSAR tool list is
   nevertheless correct; no current scan selection failure was reproduced.
5. **Prior-registry fallback — conditional existing risk.** #48's summary points to
   the workflow's tolerated missing parent/snapshot. That can omit historical-ID
   comparison if history is unexpectedly unavailable. Bootstrap cases also need a
   missing-snapshot path, and the validator logs the absence. No failing PR instance
   was demonstrated here; this is not treated as an unconditional current defect.
