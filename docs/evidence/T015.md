# T015 / LANGLO-42 · Prepared-answer evaluation

Date: 2026-10-17. Branch `claude/project-thread-ilod5c`, from main after PR 89.

## Source

The archived prepared-answer evaluator and synthetic corpus named in the task were not found in this repository, its history or the project files. With the owner's approval the evaluator was rebuilt from the matching rule every checked content module states (`matching`), and the checked content itself is the corpus.

## What changed

- `src/lib/server/evaluation/prepared.ts`: `evaluatePrepared` compares an answer with the question's checked answer and rubric alternatives and returns `correct`, `incorrect` or `uncertain`. It makes no model calls. Version `prepared-1`.
- Typed formats (typed blank, translation, correction) ignore letter case, extra spaces, apostrophe style and one final `.`, `!` or `?`. Accents (after NFC composition), inner punctuation and every other character count, so the grammar error itself is not normalised away. A typed answer that matches nothing is `uncertain`: the case the bounded fallback (LANGLO-43) evaluates.
- Multiple choice is `correct` only for the exact checked answer; any other option is `incorrect`. Options are not accepted answers.
- A question without a stored answer (imported before answers were stored) is `uncertain`.
- `recordAttempt` (`src/lib/server/study.ts`) writes one `evaluations` row in the same transaction as a new attempt: evaluator `prepared-1`, rubric = the attempt's content version. A replayed submission writes nothing; a refused attempt writes no evaluation.

## Tests

- `tests/prepared-evaluation.test.ts` (10): the rule, accents, decomposed accents, inner and repeated punctuation, multiple choice exactness (no trimming or Unicode normalization), missing answer.
- `tests/prepared-corpus.test.ts` (5) over every module in `content/`: each module's `matching` text equals the rule implemented; every answer and typed alternative is `correct`; every other multiple-choice option is `incorrect`; none of the authored near misses is `correct` (1,860 questions, 2,477 near misses at the time of writing).
- `tests/attempt-evaluation.test.ts` (6): outcome and versions stored per attempt, one row per attempt, none on replay or refusal.
- Full run on Node 22.22.0 / npm 10.9.4 (the container has no Node 24): 47 files, 932 tests passed; check, lint, format:check and build clean.
- Red checks: dropping case folding fails 4 tests; returning `correct` for every typed answer fails 3; stripping all punctuation fails 4.

## Limits

- Near misses are used only by the corpus test; they are not stored, so a near-miss answer is `uncertain`, not `incorrect`, until the fallback evaluates it.
- The rule is the same for every track today; the corpus test fails loudly if a module states a different one.
- No learner-facing feedback, mastery or skill evidence is written (LANGLO-44 and LANGLO-45). Flashcard ratings and FSRS are untouched.
