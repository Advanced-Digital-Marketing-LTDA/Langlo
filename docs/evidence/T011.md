# T011 · Owner-scoped learner repository reconciliation

Date: 2026-10-14. Tracker: LANGLO-31 (repository) and LANGLO-32/LANGLO-17 (routes). Base commit `a1e848d` (main after PR26). Code and tests only, against disposable local fixture databases. No provider, production database, credentials or real learner accounts were used.

## What was reconciled

The parent repository archive is the synthetic-principal work already in this repository: `tests/fixtures/study.ts` seeds `learner-a` and `learner-b` with raw SQL, `tests/db-owner.pbt.test.ts` and `tests/fixtures/ownership-fault.ts` prove the composite owner foreign keys, and `src/lib/server/flashcards.ts` already took a `LearnerSession`. That work is kept as it is and still counts as synthetic evidence only. This slice adds the missing pieces: a learner derived from the verified session, and an owner-scoped grammar/attempt repository.

## Changed files

- `src/lib/server/learner-session.ts` (new): `learnerSessionFrom(locals)` returns a frozen `{ userId }` built only from `locals.user` (set by the auth hook from the verified session). It returns `null` when there is no user or a blank id, or when `locals.session.userId` differs from `locals.user.id`. It takes only `locals`, so params, query and form fields cannot reach it. `requireLearnerPage` redirects 303 to `/login`; `requireLearnerApi` throws 401.
- `src/lib/server/study.ts` (new): `listStudySessions`, `getStudySession`, `listAttempts`, `getAttempt` (with its evaluations), `listEvaluations` and `recordAttempt`. Each statement binds `owner_id` to the session learner, and any id outside the learner's rows returns `StudyError('NOT_FOUND')`. `recordAttempt` checks input, then in one write transaction: replays the caller's own `submission_key` (same payload returns the original id with `duplicate: true`, a different payload returns `IDEMPOTENCY_CONFLICT`), requires the caller's own active study session, resolves the question in that session's language, and inserts with a server-generated attempt id. Content version, skill and language are copied from the question, not taken from the client.
- `src/lib/server/flashcards.ts`: added owner-scoped `listDecks` and `listReviewEvents` (immutable review history for an owned card, `NOT_FOUND` otherwise), and exported the existing `beginWrite` retry helper so `study.ts` can reuse it. Existing functions are unchanged.
- `src/routes/app/+page.server.ts`: `load` now goes through `requireLearnerPage`.
- `tests/learner-session.test.ts` (8 tests), `tests/learner-owner-scope.test.ts` (9 tests), `tests/learner-owner-scope.pbt.test.ts` (1 property, 100 runs by default), `tests/fixtures/owner-scope.ts` (an ordered snapshot of all eight private tables, used as the zero-write oracle).

## Coverage

- Session derivation: the verified user only; locals carrying `learnerId`/`userId`/`ownerId` set to another learner are ignored; a missing or blank user gives `null`; a session bound to another user gives `null`. Route helpers redirect or return 401 even when the URL query, params and POST body name `learner-b`, and return the verified learner otherwise.
- Grammar: each owner lists and reads only their own study sessions; attempts and evaluations are invisible to the other owner; a recorded attempt is idempotent per owner; submission keys are not shared across owners (B reusing A's `submit-a` creates B's own attempt); malformed input is rejected before any write.
- Forged IDs: for both owners, every foreign or guessed id (other owner's real ids, empty, whitespace, SQL-like, `%`, a user id) gives `NOT_FOUND` on study session, attempt list, attempt and evaluation reads. `recordAttempt` into a foreign session, or with a forged question, writes nothing.
- Flashcards: owner A cannot read, approve or add notes to B's deck, note or card. `submitReview` on B's card, including a reused B submission id, gives `NOT_FOUND`. B's FSRS snapshot (`state_json`, `due_at`, `revision`) and review events are byte-identical afterwards. `listReviewEvents` returns only the owner's events and no `owner_id`.
- Property: owner B guesses from A's real ids plus arbitrary strings. Every read, approve, review and attempt call fails and all eight private tables match the baseline after each case.

## LANGLO-32: session-derived private routes

- `src/lib/server/learner-api.ts` (new): `learnerApi(event, run)` takes the learner only from `requireLearnerApi(event)`, answers 503 when study data is not configured, opens the app database per request and always closes it. Repository `NOT_FOUND` becomes 404 `Not found.`; conflicts (`IDEMPOTENCY_CONFLICT`, `STALE_REVIEW`, `NOT_APPROVED`, `SUSPENDED`, `SESSION_NOT_ACTIVE`) become 409; `INVALID_*` becomes 400. `readJsonObject` rejects a body that is not a JSON object with 400 before any query, and `withoutOwner` drops `ownerId` from responses.
- JSON routes under `/app/api` (the auth hook already redirects anonymous GETs to `/login` and answers 401 to other methods):
  - `GET /decks`, `GET /notes/[id]`, `POST /notes/[id]/approve`
  - `GET /cards/[id]/reviews` (immutable events), `POST /cards/[id]/reviews` (FSRS review)
  - `GET /study-sessions`, `GET /study-sessions/[id]` (with its attempts)
  - `POST /attempts` (201), `GET /attempts/[id]` (with evaluations)
- None reads a learner, owner or user id from the path, query or body.
- `tests/learner-routes.test.ts` (7 tests) calls the handlers as SvelteKit does, with fixture principals: 401 before data, 503 without data config, own rows only, forged ids give 404 with all eight private tables unchanged, query and body `ownerId`/`userId`/`learnerId` ignored, malformed bodies 400, and owner review/attempt success including a 409 stale review.
- `tests/e2e/owner-routes.spec.ts` (4 tests per browser project) is the real-session acceptance. It provisions two accounts with `scripts/accounts-provision.ts`, signs both in through `/login` on the built server, and seeds Bob's deck, approved note, card, study session and attempt under his real account id. Alice gets 404 on each of Bob's note, card history, study session and attempt, and on approve, review and attempt writes with Bob's id in the body; the private tables are unchanged. A forged `ownerId` query lists nothing. Bob can review his own card. An anonymous caller is redirected or gets 401.

Red, before implementation (`npx vitest run tests/learner-routes.test.ts`): `Test Files 1 failed (1)`, `Tests no tests` (the route modules did not exist). Green after: `Tests 7 passed (7)`. Mutation check: making `learnerApi` honour an `ownerId` query parameter failed `ignore learner, owner and user IDs supplied by the client` (`Tests 1 failed | 6 passed (7)`); restored, green. The e2e spec was written after the routes and passed on its first run, so it has no recorded red.

The prototype e2e `kept mistake becomes an approvable draft in decks` failed once on CI because it clicked the server-rendered button before hydration. It now retries the click until the draft is announced; 5 repeated local runs of `prototype.spec.ts` passed (140/140).

## Unmet gates

- The `/app/api` routes are JSON endpoints with no UI yet; the learner app pages (LANGLO-40 onward) should call the same repositories through `learnerApi` or `requireLearnerPage`. Deck and note creation are not routed, because a note's source id depends on T021 canonical-mistake semantics. The real-session e2e seeds Bob's rows directly in the fixture database.
- The `learner-a`/`learner-b` principals in the Vitest tests are synthetic; only `owner-routes.spec.ts` uses real signed-in accounts, and those are local fixture accounts. They prove repository scoping, not authentication.
- Client-chosen deck and note ids are still global primary keys. If owner A creates a deck or note with an id owner B already uses, the insert fails with a constraint error and writes nothing, but that reveals the id exists. Server-generated ids (as `recordAttempt` already uses) or a uniform error should close this when those writes are routed.
- There is no write path yet for evaluations or skill evidence (evaluator/scoring are T017/T018). Their owner scope is covered here by read tests and the composite foreign keys only.
- No production, Turso, provider, CI or deployment verification was done.
