# T039 · Guarded Turso remote-test migration command

Date: 2026-10-14. Tracker: LANGLO-124 (internal issue 1093). Base commit `0c16e02` (main after PR25). Code and tests only: no database was provisioned or connected, no live credentials were used and no remote migration was run.

## Migration and library facts

- Inventory, in journal order: `0000_initial_study`, `0001_card_delivery_identity`, `0002_harden_persisted_invariants`, `0003_review_invariants`, `0004_material_sway`, `0005_auth_contract` (auth tables). Six entries, strictly increasing `when`.
- Installed: `drizzle-orm` 0.45.3, `drizzle-kit` 0.31.11, `@libsql/client` 0.18.0.
- Drizzle's libSQL migrator (read from `node_modules/drizzle-orm/libsql/migrator.js`) creates `__drizzle_migrations(id, hash, created_at)`, compares only the newest `created_at`, and never re-checks applied hashes. That is why the new command verifies the whole ledger itself instead of calling it.
- `client.migrate` in `@libsql/client` 0.18.0 (read from `lib-esm/hrana.js` `executeHranaBatch` and `lib-esm/sqlite3.js`) runs `PRAGMA foreign_keys=off`, `BEGIN DEFERRED`, the statements, `COMMIT`, and a `ROLLBACK` step conditioned on commit failure, for both remote Hrana and local sqlite3. Atomicity comes from SQLite's transaction. This was verified from installed source and a local rollback test, not from a live Turso run.
