# T016 / LANGLO-43 · Bounded AI fallback evaluation

Date: 2026-10-17. Branch `claude/project-thread-ilod5c`, from main after PR 91.

## What changed

- `src/lib/server/evaluation/fallback.ts`: for a typed answer the prepared evaluator left `uncertain`, asks one question through the OpenAI Decisions API and returns `correct`, `incorrect` or `uncertain`. Evaluator `decisions-1`, rubric `fallback-rubric-1`.
- The request carries only the language, format, prompt, accepted answers and the learner's answer, as one JSON text. No learner, session or account identifiers are sent. The rubric is fixed text; the answer is never part of the instructions, so an answer such as "ignore the rubric" is data. A second question asks whether the answer addresses the grader; if that is more likely than not, the result is `uncertain`.
- The model is `gpt-6-luna`, the only one the Decisions API accepts (owner decision: the cheapest model, and the Decisions API for any answer chosen from a fixed set).
- The verdict is the more probable of `correct` and `incorrect`, which makes it the highest-confidence option (owner decision). Equal probabilities are `uncertain`. Any other response shape is malformed and `uncertain`.
- Timeout 10 seconds, enforced even if the provider ignores the abort signal. Timeout, a refusal, an HTTP or network error, a malformed response or the cap being reached all leave the answer `uncertain`. Each is logged as one JSON line with the reason and no answer text. No fallback is silent.
- `src/lib/server/evaluation/usage.ts` and migration `0012_ai_usage`: a monthly call counter (cap 100,000, owner decision). A call is reserved with one atomic statement before it is sent, so concurrent requests cannot exceed the cap. Token usage is added after a valid response.
- `recordAttempt` runs the fallback after the attempt and its prepared evaluation commit, only when the prepared result is `uncertain` and the question is typed with a stored answer. A slow or failed call never loses the answer. A verdict is stored as its own `evaluations` row next to the prepared one.
- `OPENAI_API_KEY` is optional runtime config. Unset, the fallback logs `not-configured` and the answer stays `uncertain`.
- No mastery, skill evidence or mistake card is written (LANGLO-44 and later). Prepared matches, multiple choice and replayed submissions make zero AI calls.
