## Behavior

- Gates, each rejecting the whole package with a `ContentImportError` code:
  - `NOT_APPROVED`: the package `publicationStatus` is not `approved`, or `curriculumVersion` is not a stable semantic version (the contract requires one for an approved bundle).
  - `INVALID_PACKAGE`: edges are not `recommended_teaching_order`; malformed skills, versions or questions; a skill outside the contract's five tracks (French A1, German A1–A2, English A1–A2); a skill listing the same prerequisite twice; a version with no questions; duplicate IDs; an unknown question format.
  - `UNREVIEWED`: a skill that is not `approved`, or a version that is neither `approved` nor `quarantined`.
  - `MISSING_REFERENCE`: a prerequisite or version names a skill that is neither in the package nor stored.
  - `INVALID_PREREQUISITE`: a cross-language edge, or a higher-level skill required by a lower one.
  - `PREREQUISITE_CYCLE`: self-edges and cycles, checked over stored edges plus the package's edges.
  - `INVALID_ALTERNATIVES`: multiple choice needs at least two unique alternatives (trimmed, case-insensitive) that include the answer; other formats may list accepted alternatives, which must be unique, non-empty and different from the answer.
  - `CONTENT_CONFLICT`: the package would change a stored skill's language or level, change a stored version's skill, number or question set, reuse a skill/version number under another ID, or reuse a stored question ID.
- Idempotent: re-importing the same package returns all-zero counts and leaves the content tables identical.
- Prerequisites are only added (`INSERT OR IGNORE`), never removed, so a later package that omits an edge keeps it.
- New versions are added alongside older ones; stored versions are immutable.
- Imported versions get status `schema-validated`. Promotion to `pilot-ready` is not part of import.
- Quarantine is one-way: a package marking a stored version `quarantined` sets it, and a later package marking it `approved` does not undo it. Attempts on quarantined questions already return `CONTENT_UNAVAILABLE` (T011).
- No learner data: the test compares all eight owner-scoped tables (cards, review events, study sessions, attempts, evaluations, skill evidence) before and after an import, and they are identical. The importer never touches FSRS state.

## Unmet gates

- No checked curriculum: the bundle is `0.1.0-draft.1` (draft), so no real content has been imported. The evidence is synthetic and covers zero checked curriculum. LANGLO-34's acceptance needs the five-track audit and approved content (LANGLO-35 to 39).
- Lessons: migration 0005 has no lesson table, so the importer imports no lessons. Lesson schema belongs with LANGLO-40.
- Question payload: prompt, answer and alternatives are validated but not stored, so a re-import that changes only a stored question's prompt, answer or alternatives is not detected (nothing about them is stored to compare against). The reason is that `questions` has no payload or rubric column. Storing the payload (or a fingerprint of it) and serving checked questions both need a migration.
- The importer does not yet read the `content/` bundle or check the manifest hashes. Wiring `scripts/curriculum-contract.mjs`'s `validateBundle` in front of it, plus a fixture-only CLI, is left for LANGLO-34.
- Local checks do not prove CI, a remote database or release success.
