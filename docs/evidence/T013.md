# T013 / LANGLO-40 · Resumable lessons and sessions

Date: 2026-10-16. Branch `claude/project-thread-ilod5c`, from main after PR 85. Owner decisions (2026-10-16): lessons live in the database; Portuguese enrollments see English with a visible notice; sessions do not expire.

## What changed

- Migration `0010_lessons_and_pause.sql` (and `0011_one_independent_attempt.sql`, below): new `lessons` table and nullable `study_sessions.paused_at`. Additive; no table rebuilt, no earlier migration edited.
- Importer: an optional `lesson` on each package version is validated, stored with its own fingerprint, and immutable once stored (`CONTENT_CONFLICT` on a changed text). A version without a lesson may gain one under a new curriculum version. Packages without lessons keep their fingerprints.
- Study service: `pauseStudySession`, `resumeStudySession`, `nextQuestion`, `getLesson`.
- Routes: `POST /app/api/study-sessions/[id]/pause|resume`, `GET .../next?skill=`, and the page `src/routes/app/learn/[language]/lesson/[skill]/`. The issue names `src/routes/(app)/learn/...`; the repository's private surface is `src/routes/app/`, so the page lives there.

## Behavior

- Resume position is derived from confirmed attempts. A reload or second tab recomputes the same next item; the existing idempotent submission key prevents double counting.
- `nextQuestion` never returns the answer and excludes holdouts outside assessment sessions. Paused sessions get `SESSION_NOT_ACTIVE`.
- Pause keeps the first pause time on repeat; resume clears it; completed sessions cannot be paused or resumed. Another learner's session is `NOT_FOUND` and unchanged.
- The lesson page shows English with a notice for non-English enrollments and an honest notice for quarantined content. It renders no exercise controls (LANGLO-41).

## Review follow-up (same PR)

- Content withdrawn between the version check and the payload read is no longer served: the version status is read in the same statement as the question or lesson (`nextQuestion`, `getLesson`).
- A skill a session has started stays on the content version of its first attempt, so resuming across a newer import does not restart it. A session that has not started the skill reads the newest version. A quarantined pinned version still answers `CONTENT_UNAVAILABLE`.
- `recordAttempt` rejects a question of another version than the one the session's first answer for the skill pinned (`STALE_QUESTION`, 409), and `nextQuestion` reads the session state in its payload statement so a pause committed during the read is not answered with a question.
- Migration `0011_one_independent_attempt.sql` adds a partial unique index: one `independent` attempt per owner, session and question. Assisted retries are unaffected. `recordAttempt` checks the same rule first and answers `QUESTION_ALREADY_ANSWERED` (409). The migration fails loudly on a database that already holds two independent attempts for one session question.
- Lesson example keys are sorted before hashing and storing, so a re-import with reordered keys is the same lesson.
- Pause and resume answer `SESSION_NOT_ACTIVE` when the update changes no row. Paused, withdrawn and already-answered reads have their own 409 messages.
- Two existing tests were adjusted because the one-independent-answer rule applies to them: the forged-version insert in `tests/db-constraints.test.ts` now uses `assisted` so the foreign key is what rejects it, and two attempt-recording tests (`learner-owner-scope`, `learner-routes`) answer `question-2`, which `study-a` had not answered. The legacy-upgrade test excludes the new index from its before and after comparison, as it does for the lessons autoindex.
