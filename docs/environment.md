# Runtime environment registry

All application values are explicit private dynamic declarations in src/env.ts, exposed server-only through $app/env/private. hooks.server.ts validates them at the request boundary, except /health/live, which remains dependency-independent even when configuration is invalid. config.ts is server-only. No provider/account identifiers are embedded in client assets.

The application, Compose service, content importer and remote-test migration tool require `TURSO_AUTH_TOKEN_2` for remote database authentication. The previous `TURSO_AUTH_TOKEN` name is no longer read. Operators upgrading a direct runtime or CLI environment must rename that variable before enabling remote data access; Compose already sources its value from `TURSO_AUTH_TOKEN_2` on the host. This change does not update any deployed environment or rotate a token.

No separate analytics, billing, OAuth or Anki integration is activated. The SMTP transport is wired but has never been exercised against a live provider; capture remains the only verified mail path. Private environment configuration is not permission for live integration or production access. Storage resources and credentials must be provisioned separately under explicit authorization. APP_BUILD_SHA is safe provenance only, never evidence that a release occurred.

SMTP delivery errors after a recovery request starts are logged as `mail-delivery` diagnostics without changing the response shared by known and unknown addresses. This preserves enumeration resistance but does not confirm delivery. See [auth.md](auth.md#6-provisioning-and-mail-delivery) for the current limitation.

Framework/adapter sources inspected 2026-10-06: https://svelte.dev/docs/kit/adapter-node and https://svelte.dev/docs/kit/server-only-modules. Node adapter uses runtime environment; production .env loading requires an explicit documented operator mechanism. Reverse-proxy trust settings remain a deployment gate.

## Playwright browser environment

`npm run test:e2e` and direct `npx playwright test` use the same repository setup. On Linux, `playwright.config.ts` supplies each invocation's browser processes with a fresh `XDG_CACHE_HOME` under the resolved system temporary directory. This prevents the browser from reusing incompatible mounted Fontconfig user caches. The runner's own `XDG_CACHE_HOME`, browser-download location, npm cache and desktop configuration remain unchanged. No fonts are copied or downloaded by this setup.

The runner passes an internal `LANGLO_PLAYWRIGHT_FONT_CACHE` marker to workers so they share the run's cache without creating or deleting each other's directories. It is not an operator setting. Only the process that allocated the temporary directory owns cleanup. Normal teardown and setup failure remove the owned cache; a process-exit fallback also covers listing tests and failures before setup. Cleanup never removes the incoming host cache.

Before the scenarios start, the global setup launches Chromium with the configured launch options, renders a small heading and checks for positive width and height. Missing fonts, zero-height text or a browser launch failure stop the run with `Playwright browser preflight failed` and the original cause. The preflight runs on every platform; cache isolation is Linux-only. It does not skip tests or change assertions, retries or application behavior.

`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` still selects an optional installed Chromium executable. Explicit `FONTCONFIG_FILE` settings are preserved; an unusable custom configuration will fail preflight rather than silently falling back. If the browser or OS libraries are missing, install them with `npx playwright install --with-deps chromium` on a supported host. Cache isolation cannot supply missing system libraries or fonts.
